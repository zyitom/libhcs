# hpm5321 单镜像共存：libhcs + DMTool FDCAN 仿真 + CDC

## 已确认的关键事实

1. **gs_usb 路线已排除**：DMTool 无 gs_usb 主机协议实现（无控制传输、无 gs_host_frame），其 GSCAN 设备走同一套 A5/5A 私有协议。实现 DM 私有协议是获得 FDCAN 全功能的唯一途径。
2. **性能**：用户确认 libhcs 与 DMTool 不同时跑。bulk 端点仅在被 host 挂 URB 后才被轮询（xHCI 语义），不跑的一边零代价。唯一必改项：CDC notify bInterval 1→16（TinyUSB 默认 8000 次/秒空轮询）。

## 架构（单镜像，无编译开关）

设备 VID/PID = **0x34B7 : 0x6877**（DMTool 仅查 VID/PID；product string 保持 "HCS Agent v<ver>" 作为 libhcs discriminator）。6 接口 / 端点 10/16：

| 接口 | 用途 | 端点 |
|---|---|---|
| If0 | DM 心跳/CAN 数据流 | 0x01 OUT / 0x81 IN（DMTool 硬编码） |
| If1 | DM 命令/ACK | 0x02 OUT / 0x82 IN |
| If2 | DM CAN-TX/错误流 | 0x03 OUT / 0x83 IN |
| If3 | libhcs vendor（搬迁） | 0x04 OUT / 0x84 IN |
| If4 | CDC（UART 桥 + 串口助手） | 0x05 OUT / 0x85 IN / 0x86 notify(bInterval=16) |
| If5 | DFU runtime | — |

host 侧改动：`hpm5321.hpp` VID/PID → 0x34B7/0x6877；`usb.cpp:1668-1671` kTargetInterface 0→3、kOut 0x01→0x04、kIn 0x81→0x84。EP0 握手协议不变，product string 匹配逻辑不变。

## Phase 0：逆向收尾 → DMTOOL_PROTOCOL.md

objdump 补齐剩余 ~20%：TX 22B 帧头逐字节、RX 头标志/通道/方向、ACK 与版本字符串格式、GetBaudRate/UUID/SnCode 应答、错误帧。用真适配器抓完整会话 pcap 对拍定稿（用户已确认有真适配器）。

## Phase 1：固件描述符

`tusb_config.h`：`CFG_TUD_VENDOR=4` + `CFG_TUD_CDC=1`；`usb_descriptors.*`：6 接口（FS/HS 两套），跳过 OTP PID 补丁；`app/CMakeLists.txt` 加 `cdc_device.c`。

## Phase 2：DM 协议引擎（新 `app/src/dmtool/`）

A5/CMD/LEN16/payload/CRC16-IBM/5A 状态机；vendor 实例路由（itf0=心跳+数据、itf1=命令、itf2=CAN-TX）；命令 0x00–0x10（SETUP_BUARD→位时序换算、版本不含 "boot"、0x0C→BootMailbox、0x0D 回读）；ACK 走 0x82。

## Phase 3：CAN 数据面

EP3 OUT→解析→复用 `can::can_array[ch]` TX 队列；MCAN RX ISR→DM RX 帧（16B 头 + 64 位 ns 时间戳，PTPC0 TSU 已有）→0x81 IN；RX 扇出到 libhcs uplink 与 DM 流（独立开关）；TX 回显 v2。

## Phase 4：CDC ↔ UART 桥

`tud_cdc` 回调只搬环形缓冲，处理在主循环；对接 `uart::uart_array`。

## Phase 5：验证

1. 编译（固件 + host SDK）
2. 真适配器 pcap 对拍 → DMTool 全功能走查（版本→波特率→通道→采集→收发→时间戳）
3. libhcs 回归：probe p50 对比基线
4. 三态验证：DMTool 关（=基线）/ 开而闲置 / 活跃
